# Neovim キーバインドつかいこなせてないやつメモ

## 変更履歴 (2026-05-04)

### 1. Telescope 検索系キーマップ追加

変更前は `<leader>t` (コマンド一覧) と `<leader>f` (file_browser) のみだった。
Telescope の本領は**ファジー検索**なので、主要な検索系を `<leader>f` 配下に統一した。

| キー | 機能 | 使いどころ |
|------|------|-----------|
| `<leader>ff` | find_files | **最頻出**。ファイル名の一部を打つだけで開ける |
| `<leader>fg` | live_grep | プロジェクト全体からテキスト検索。関数名・エラーメッセージ等 |
| `<leader>fb` | buffers | 開いているバッファの切り替え。タブバーよりも速い |
| `<leader>fh` | help_tags | Neovim のヘルプをファジー検索 |
| `<leader>fd` | diagnostics | LSP の警告・エラー一覧 |
| `<leader>fs` | lsp_document_symbols | 現在のファイル内の関数・型・変数の一覧 |
| `<leader>fr` | lsp_references | カーソル下のシンボルの参照箇所 |
| `<leader>fo` | oldfiles | 最近開いたファイル |
| `<leader>fe` | file_browser | ディレクトリを辿ってファイル操作 (旧 `<leader>f`) |
| `<leader>ft` | Telescope commands | Telescope の全コマンド一覧 (旧 `<leader>t`) |

#### 使いこなしのコツ

- **ファイルを開くとき**: まず `<leader>ff` を試す。名前の一部(2-3文字)で十分絞れる
- **コード内の文字列を探すとき**: `<leader>fg` で live_grep。入力中にリアルタイムで結果が絞られる
- **バッファ切り替え**: `<leader>fb` → ファイル名の一部を打つ。`gt`/`gT` より速い場面が多い
- **「この関数どこで使われてる？」**: カーソルを関数名に置いて `<leader>fr` または `gr`
- **「このファイルにどんな関数がある？」**: `<leader>fs`
- Telescope 内では `<C-n>`/`<C-p>` で候補移動、`<CR>` で決定、`<C-f>` (Esc) でキャンセル

### 2. LSP キーマップ: 頻出操作のプレフィックス撤廃

変更前は全て `<leader>l` プレフィックス付きだった (例: `<leader>lgd`)。
頻出操作はプレフィックスなしに変更し、2キーストローク削減した。

#### プレフィックスなし (頻出・即座にアクセスしたいもの)

| キー | 機能 | 使いどころ |
|------|------|-----------|
| `gd` | 定義にジャンプ | 関数・変数の定義元を見たいとき。**最も使う** |
| `gD` | 宣言にジャンプ | C言語等でヘッダの宣言に飛びたいとき |
| `gi` | 実装にジャンプ | インターフェースから実装に飛ぶ |
| `gr` | 参照一覧 | 「この関数/変数はどこで使われている？」 |
| `K` | ホバードキュメント | カーソル下のシンボルのドキュメント表示 |
| `<C-s>` | シグネチャヘルプ | 関数の引数情報を表示 |
| `[d` / `]d` | 診断ジャンプ | 前/次の警告・エラーに飛ぶ |

#### `<leader>l` プレフィックス付き (低頻度)

| キー | 機能 |
|------|------|
| `<leader>lrn` | リネーム |
| `<leader>lca` | コードアクション |
| `<leader>lF` | フォーマット |
| `<leader>lD` | 型定義にジャンプ |
| `<leader>ldl` | 診断フロート表示 |
| `<leader>lq` | 診断を loclist に送る |
| `<leader>lwa/wr/wl` | ワークスペースフォルダ管理 |

#### 使いこなしのコツ

- **コードリーディングの基本フロー**: `gd` で定義に飛ぶ → `<C-o>` で戻る → `gr` で参照を確認
- **K** は「これ何だっけ？」と思ったらすぐ押す。型情報やドキュメントが見える
- **`[d`/`]d`** でエラー箇所を巡回 → `<leader>ldl` で詳細確認 → `<leader>lca` で自動修正

### 3. `y` (yank) の標準動作を復元

変更前は `y` が無効化され `yy` でしかヤンクできなかった。
標準の `y` + motion を復元した。

#### 覚えるべき y の使い方

| キー | 動作 | 説明 |
|------|------|------|
| `yy` | 行ヤンク | 現在行をコピー (変更なし) |
| `yw` | 単語ヤンク | カーソルから単語末尾まで |
| `yiw` | 単語全体ヤンク | カーソル位置の単語全体 |
| `yi"` | 引用符内ヤンク | `"..."` の中身をコピー |
| `yi(` | 括弧内ヤンク | `(...)` の中身をコピー |
| `yi{` | 波括弧内ヤンク | `{...}` の中身をコピー |
| `yap` | 段落ヤンク | 段落全体をコピー |
| `y$` | 行末までヤンク | カーソルから行末まで |
| `y0` | 行頭までヤンク | カーソルから行頭まで |

**パターン**: `y` + テキストオブジェクト。`d` (削除) や `c` (変更) も同じ文法で使える。
例: `diw` (単語削除)、`ci"` (引用符内を変更)、`da(` (括弧ごと削除)

### 4. aerial のシンボルジャンプキーを変更

変更前は `{`/`}` を aerial (シンボルジャンプ) に上書きしていた。
`{`/`}` は Vim 標準の段落移動なので、aerial は `[s`/`]s` に変更した。

| キー | 機能 |
|------|------|
| `{` / `}` | 段落移動 (Vim 標準に復元) |
| `[s` / `]s` | aerial: 前/次のシンボルにジャンプ |
| `<leader>o` | aerial: アウトライン表示トグル |

`[s`/`]s` は `[d`/`]d` (診断ジャンプ) と対になるので覚えやすい。
