# LLM Wiki（AIに読ませる知識ベース）

`khimoo/llm-wikis`（プライベートリポジトリ）を `~/sagyo/llm-wikis` に配置し、ドメインごとの知識ベースを Claude に構築・更新させます。
二次情報で記述が食い違っている領域や、Claude がデフォルトで誤答しやすい分野について、調査結果を蓄積して次回以降の参照用として活用します。

設計：[LLM Wiki の設計](../architecture/llm-wikis.md)

## 配置

`clone-repos` により `local.profile.llmWikisRepoUrl` から `llmWikisRoot` へクローンされます（詳細は [private-repo-clone.md](./private-repo-clone.md) を参照）。

```
llm-wikis/
  CLAUDE.md                 ルーター。ドメインディレクトリで作業させるための指示のみ
  minecraft-java/
    CLAUDE.md               このドメインの Wiki スキーマ
    raw/<topic>/            収集した一次資料（不変。LLM は読み取りのみ）
    wiki/<topic>/*.md       記事ファイル（LLM が管理・更新）
    wiki/index.md           全記事の目録
    wiki/log.md             追記専用の操作ログ
```

`raw/` および `wiki/` 配下のトピック別サブディレクトリは 1 階層までに制限されています。

`~/.claude` へのシンボリックリンクなどの配線はありません。スキーマはカレントディレクトリの `CLAUDE.md` として読み込まれます。

## 使い方

対象ドメインのディレクトリへ移動し、Claude Code を起動します。

```sh
cd ~/sagyo/llm-wikis/minecraft-java && claude
```

起動後、主に以下の 3 つの操作を行わせます。

| 操作 | 依頼内容 | 実行される処理 |
|---|---|---|
| ingest | 資料の URL を渡して「取り込んで」と依頼する | 資料が `raw/` に保存され、記事が作成・更新されます。併せて `index.md` と `log.md` も更新されます。 |
| query | 通常の質問をする | `wiki/` 内を参照して回答します。確証のあるページがない場合は「情報がない」と回答します。 |
| lint | 「lint して」と依頼する | インデックスのズレやリンク切れを自動修正し、記事間の矛盾、確信度（confidence）、バージョン表記の不備を報告します。 |

query の回答が Wiki 内に存在しなかった場合、その場で調べた結果を**そのまま Wiki に追加してはいけません**。
必ず一次資料を `raw/` に配置してから ingest してください。推論で補完したページが次回以降の出典になってしまうことが、このパターンの最大の失敗原因となるため、ワークフローを厳格に分離しています。

## 新しいドメインの追加手順

1. `llm-wikis/` 直下にドメイン名のディレクトリを作成します。
2. 既存ドメインの `CLAUDE.md` をコピーし、対象領域・確信度（confidence）の判定基準・バージョン表記を書き換えます。併せて `raw/` と `wiki/index.md` / `wiki/log.md` も用意します。
3. ルートの `CLAUDE.md` にあるドメイン一覧表に 1 行追加します。

flake 側の設定変更は不要です。リポジトリ全体が 1 つのクローン対象であるため、ドメインが増えても設定（配線）は変わりません。

## スキーマに必ず含めるべき項目

`<domain>/CLAUDE.md` を作成する際、以下の記述が抜けていると予期せぬトラブルにつながります。

- **確信度（confidence）をページ内にインラインで記述させる**：別ファイルに分離すると、本文だけを読み込んだ際に断定的に解釈されてしまいます。
- **確信のある回答がない場合は「情報がない」と答えさせる**：関連性の低い情報からの安易な推論を禁止します。
- **全記事に対象バージョン（`Version:`）と更新日（`Updated:`）を明記させる**
- **AI が陥りやすい誤りを明示的に記述させる**：Wiki を見れば分かる内容の転記よりも、デフォルトの挙動を修正する情報のほうが役立ちます。
- **Wiki 内の数値や引用が `raw/` 内に全く同じ形で存在することを確認させる**：`raw/` を不変（Immutable）に保つのは、この対応関係を維持するためです。

## 無効化（削除）手順

各自の `local.profile.llmWikisRepoUrl` 設定を削除（デフォルト値 `null`）すると、`clone-repos` の対象から外れます。
`llmWikisRoot` の参照はクローン処理時のみ行われるため、両方の設定を削除して問題ありません。
