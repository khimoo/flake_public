# 写真の仕分け

Google Photos から引き上げた写真アーカイブを digiKam で見て、要るものと要らないものを分ける。

## 原本と作業用ツリー

原本は `~/ダウンロード` の zip 3 本。

| zip | 中身 |
|---|---|
| `takeout-20260821T155848Z-1-001.zip` | 通常の写真・動画（年ごとのフォルダ）とロックされたフォルダの一部 |
| `Photos-1-001.zip` / `Photos-1-001(1).zip` | ロックされたフォルダの別系統 |

同じものが USB（ラベル KIOXIA）にもある。**この 2 か所以外に原本は無い。**

仕分けは `/mnt/backup/photos` に展開した派生ツリーで行う。zip には触らないので、消しすぎても展開し直せば戻る。躊躇せず消してよい。

## このアーカイブの性質

### 年は分かる、日時は分からない

Takeout は `2015 年の写真` から `2026 年の写真` までのフォルダに分けて出してくる。年で絞るだけならこれで足りる。

一方でファイルの更新日時はエクスポートした日（2026-08-21）に潰れていて、撮影日時は `<ファイル名>.supplemental-metadata.json` に分離されている。digiKam の日付順やタイムラインは当てにならない。直すなら exiftool でサイドカーから EXIF へ書き戻すことになるが、年フォルダで用が足りるうちはやらなくてよい。

### 容量の 66% は動画

| 種類 | 本数 | 容量 |
|---|---|---|
| 動画 | 276 | 19.2 GiB |
| 写真 | 3569 | 9.5 GiB |

容量を減らしたいなら動画だけ見ればよく、276 本なら一度に見切れる。写真を 1 枚ずつ選別しても効果は薄い。年別では 2022 年（7.4 GiB）と 2023 年（6.6 GiB）が重い。

### ロックされたフォルダは 2 系統あり、どちらも片方では足りない

takeout の中の `ロックされたフォルダ` に 132 本、別 zip 2 本に 138 本。うち 112 本は名前もサイズも同一なので、両方展開すると 3.3 GiB が二重になる。別 zip にしか無いものが 26 本（714.8 MiB）、takeout にしか無いものが 20 本あるため、どちらも捨てられない。

別 zip の側には `.json` サイドカーが 1 つも無い。この 26 本の撮影日時は復元できない。

## 展開する

`unzip` は使わない。日本語のフォルダ名が `???` に化ける（このビルドは iconv 無効で `-O UTF-8` も効かない）。7z を使う。

```sh
pkexec /run/current-system/sw/bin/bash -c \
  'mkdir -p /mnt/backup/photos && chown pomu:users /mnt/backup/photos'

cd /mnt/backup/photos
7z x ~/ダウンロード/takeout-20260821T155848Z-1-001.zip
7z x -o'locked-alt' ~/ダウンロード/Photos-1-001.zip
7z x -o'locked-alt' '~/ダウンロード/Photos-1-001(1).zip'
```

別 zip を自前のフォルダに出すのは、root 直下にファイルを並べる作りだから。そのまま展開すると `Takeout/` と同じ階層に 138 本が散らばる。

展開後は 28.7 GiB。`/mnt/backup` の空きは 79 GiB。

## digiKam で仕分ける

初回起動でアルバムの置き場所を聞かれるので `/mnt/backup/photos` を指定する。digiKam はディレクトリをそのままアルバムとして見るだけで、ファイルを動かさない。データベースは別に作られる。

動画から手を付ける。サイズ順に並べると先頭に固まる。動画のサムネイルも写真と同じグリッドに出るので、見て消していけば容量の 66% を処理できる。

重複は Tools の重複検出で潰す。ロックされたフォルダの 112 本がここで出る。

削除はまず digiKam 内のゴミ箱に入り、空にするまでディスクからは消えない。
