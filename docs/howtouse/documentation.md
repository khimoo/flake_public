# 文書の整備

設計: [構成の境界](../architecture/configuration.md)
共通指示: [AGENTS.md](../../AGENTS.md)

人とエージェントは同じ文書と手順を使います。Claude Code では `/workflow <tool>`、それ以外では通常の文書整備の依頼で、この手順を利用できます。コマンドの明示実行は対象の文書編集の依頼です。設定の編集は、ユーザーが既に許可した範囲でのみ行います。

## 対象を確かめる

対象の実装、既存の使い方・設計文書、各索引を読み、用途、有効化条件、対応 OS、キー操作、設定変更・適用に必要な操作、無効化・復旧手順を確認します。過去の記録だけで現在の挙動を断定せず、実装と照合します。確認できない点や未実装の案は、その状態を明記します。確かめた事項のうち、文書に書くのは次の節の基準に当たるものだけです。

## 書く内容を選ぶ

文書に残すのは、将来の操作や判断に必要で、調べ直すのが高くつく情報です。

- 使い方の文書は、操作するための文書です。実行するコマンド、変更する設定の場所、前提、成功したかの確かめ方、失敗したときに見る場所を書き、場面ごとに節を分けます。
- 設計の文書は、判断を引き継ぐための文書です。現在の決定と、それを変える前に知っておくべき理由を書きます。版を示して確かめた上流の挙動、ユーザーが選んだこと、観測した事実のように調べ直しにくい根拠も残します。退けた案と見直す条件は、実際にあるときだけ書きます。
- コードを読めば分かること（設定ファイルの一覧、モジュールの責務、設定値の書き写し）は書きません。作業の経緯（以前の構成、日付つきの作業記録、計測の過程）はコミットメッセージに書きます。

## 配置と参照を整える

- 使い方と操作手順は [使い方ガイド](README.md) 配下、採用理由・代償・根拠は [設計判断](../architecture/README.md) 配下に置きます（小さな機能は下の例外）。
- Neovim 固有のキーやプラグインの文書は [config 配下](../../modules/home-manager/dev/neovim/config/docs/README.md) に置きます。
- 対応する使い方・設計文書を相互に結び、実装へはローカルリンクを付けます。ファイルの追加・削除に合わせて索引も更新します。
- 設定を挙動の正本、詳細文書を使い方と判断理由の説明、索引を案内として扱い、詳細な表や手順を複写しません。コードコメントにはその箇所で必要な理由を書き、長い背景は設計文書へリンクします。
- 小さな機能は使い方の文書一つにまとめ、採用理由・退けた案・代償は同じ文書の「設計」の節に書きます。使い方と設計のどちらかが長くなり、一文書では読みにくくなったら分けます。
- 索引には文書の目的だけを一文で書きます。キー操作、手順、設定値、判断の結論や理由は詳細文書にあり、索引へ書き写しません。
- ローカルメモリを規約や索引の正本にしません。判断の前提と見直す条件は、共有する対象文書に残します。

## 確認と報告

検証は [検証ガイド](validation.md) に従って変更範囲から選びます。ユーザーが検証省略を指定した場合は、その指定に従います。

変更内容、確認結果、未確認・未検証事項、ユーザーの適用や実機確認が必要な部分を報告します。
