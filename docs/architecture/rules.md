# flake_public のあるべき姿

flake_public は、複数のマシンの構成を管理する。
この文書は、flake_public が満たす要件と、要件を満たすために守る二つの規則（規則 A と規則 B）を書く。
規則 A と規則 B をどう実現するかは書かない。

## 要件

1. 変更の範囲をたどれる: 部品を変えたとき、影響を受ける部品を、部品どうしのつながりをたどって特定できる。
2. 行動をやめると専用の設定値も消える: 利用者が行動をやめると、利用者の行動のためだけにマシンに入っていた設定値も、マシンから消える。
3. 記憶に頼らない: 部品どうしの関係を、人が覚えておかなくてよい。
4. 保証の範囲が分かる: 何が保証され、何が保証されないかがはっきりしている。
5. 管理の負担を増やさない: 部品どうしの関係を記録する一覧表を、部品とは別に作らなくてよい。
6. 行動の単位で選べる: 利用者は、ホストごとに、行動の単位でマシンの構成を選べる。

## 言葉

- ホスト: 構成の対象になるマシン一台。
- 利用者: ホストのユーザーアカウント一つ。ホストごとに一人以上いる。
- 部品: マシンの構成を組み立てる単位。部品はマシンに入ると、マシンの構成に設定値を加える。
- ホスト全体の設定値: ホストのすべての利用者に適用される設定値。
- 利用者の設定値: 一人の利用者だけに適用される設定値。
- 行動: 利用者がマシンで行うこと。行動も部品の一つである。利用者は、ホストごとに、ホストで行う行動を選ぶ。
- 機体: マシンそのものを表す部品。ホストごとに一つある。
- 判定: ホストの利用者一人と部品一つの組ごとに決まる真偽。以下、「利用者 U について部品 X の判定」と書く。
- 公理: 無条件で真になる判定。利用者 U については、利用者 U が選んだ行動の判定と、ホストの機体の判定が公理になる。
- 推論規則: 「部品 X1 から部品 Xn までの判定がすべて真ならば、部品 Y の判定も真」という形の規則。「ならば」の前に書く判定を前件、「ならば」の後に書く判定を後件と呼ぶ。前件は一つ以上、後件は一つである。前件と後件は、同じ利用者についての判定である。推論規則は、前件の部品か後件の部品の定義に書かれる。
- 受け取る: 部品 X が、部品 Y の公開する値を使って、部品 X の設定値を決めること。
- 渡す: 部品 X が部品 Y に値を渡し、部品 Y が渡された値を使って部品 Y の設定値を決めること。
- 利用者によって変わる値: 利用者の名前やホームディレクトリのように利用者ごとに異なる値と、利用者ごとに異なる値から作った値。

## 規則 A（部品がマシンに入るか否か）

利用者 U について部品の判定が真になるのは、利用者 U についての公理と推論規則だけを使って、判定が真であると導けるときに限る。
利用者 U についての公理と推論規則だけでは真であると導けない判定は、偽とする。
ホストの利用者の一人以上について判定が真の部品だけが、マシンに入る。
部品のホスト全体の設定値は、部品がマシンに入るときに加わる。
部品の利用者の設定値は、部品の判定が真の利用者にだけ加わる。

## 規則 B（部品の設定値を決めるもの）

利用者 U について判定が真の部品 X が、利用者 U に加える利用者の設定値は、次のものだけで決まる。

- 部品 X の定義
- 利用者 U について判定が真の部品から、部品 X が受け取った値
- 利用者 U について判定が真の部品が、部品 X に渡した値

マシンに入る部品 X が加えるホスト全体の設定値は、次のものだけで決まる。

- 部品 X の定義
- マシンに入る部品から部品 X が受け取った値のうち、利用者によって変わらない値
- マシンに入る部品が部品 X に渡した値のうち、利用者によって変わらない値

## 規則から導かれる性質

1. 推論規則の前件に書けるのは、部品の判定だけである。値（ホスト名や利用者の名前など）は推論規則の前件に書けないので、判定は値では決まらない。値を見て部品の設定値をすべて空にすることは、判定を値で決めることにあたり、規則 A に反する。利用者の名前を見て、一部の利用者について利用者の設定値をすべて空にすることも、規則 A に反する。値を見て設定値の一部を変えることは、規則 B の範囲に入る。
2. 推論規則の前件に「部品の判定が偽」は書けない。利用者が選ぶ行動を減らしても、どの利用者についても、判定が新しく真になる部品はない。
3. 一つの推論規則の前件に複数の判定を書くと「かつ」になる。部品 Y を後件に持つ推論規則が複数あると、部品 Y の判定は、どれか一つの推論規則の前件がすべて真のときに真になるので、「または」になる。
4. 推論規則の前件と後件は同じ利用者についての判定なので、別々の利用者の行動を合わせて真になる判定はない。利用者 U1 が行動 P を選び、利用者 U2 が行動 Q を選んでも、「P かつ Q ならば R」の推論規則で R の判定が真になる利用者はいない。
5. 機体の判定はすべての利用者について公理なので、機体からだけ導ける部品の判定は、すべての利用者について真になる。

## 扱っていない課題

- [ ] ほかのホストの利用者だけが使う部品（自分用サーバの部品）は、使う利用者がいなくなっても、置いたホストに残り続ける。判定はホストごとに、そのホストの公理だけから導くので、ほかのホストで行動をやめたことは、サーバの部品の判定に届かない。サーバの部品を消すには、サーバのホストの利用者が、サーバの部品を導く行動をやめる。

## 要件と規則の対応

| 要件 | 規則からどう導かれるか |
|---|---|
| 1. 変更の範囲をたどれる | 規則 A により、部品の判定を変えるのは推論規則だけである。規則 B により、部品の設定値を変えるのは、部品の定義と、受け取る値と、渡される値だけである。部品を変えたときに影響を受ける部品は、推論規則と、受け取る関係と、渡す関係をたどって特定できる。 |
| 2. 行動をやめると専用の設定値も消える | 性質 2 により、利用者が行動をやめても、判定が新しく真になる部品はない。利用者について行動の判定が偽になると、利用者について行動からしか導けない部品の判定も偽になる。規則 A により、判定が偽になった部品の利用者の設定値は、利用者に加わらなくなる。ほかの利用者について判定が真でなければ、部品はマシンに入らず、部品のホスト全体の設定値も加わらない。規則 B により、マシンに入らない部品が渡していた値も使われなくなる。ほかの行動からも導ける部品は、判定が真のまま残る。 |
| 3. 記憶に頼らない | 部品どうしの関係は、推論規則と、受け取る関係と、渡す関係だけである。推論規則と、受け取る関係と、渡す関係は、部品の定義に書かれるので、人が別に覚えておく関係はない。 |
| 4. 保証の範囲が分かる | 保証するのは、規則 A と規則 B が成り立つ範囲である。「規則が保証しないこと」に挙げたものは保証しない。 |
| 5. 管理の負担を増やさない | 推論規則と、受け取る関係と、渡す関係は部品の定義に書かれ、部品とは別の一覧表はない。 |
| 6. 行動の単位で選べる | 利用者 U についての公理は、利用者 U が選んだ行動の判定と、ホストの機体の判定だけである。利用者は行動を選ぶことで、マシンの構成を選ぶ。 |

## 規則が保証しないこと

- 実行時の依存: マシンの上で動くプログラムが、実行時にほかのプログラムを名前で呼ぶこと。実行時の依存は、推論規則にも、受け取る関係にも、渡す関係にも現れない。
- 実行時に作られる状態: キャッシュや、プログラムが動作中に作るファイル。
- 利用者のデータ: 部品がマシンに入らなくなったときに利用者のデータを消してよいかは、規則 A と規則 B からは決まらない。
- 外から持ち込む部品の内部: 外から持ち込む部品が、外から持ち込む部品の既定値で有効にしているもの。

## 規則が決めないこと

- どの部品とどの部品を推論規則でつなぐかは、人が決める。必要な推論規則が欠けていると、行動をやめたときに、ほかの行動が必要とする部品の判定も偽になり、ほかの行動で何かが動かなくなる。不要な推論規則があると、行動をやめても、行動のためだけに入っていた部品の判定が真のまま残る。不要な推論規則は何も壊さないので、気づきにくい。
- いつもマシンに入れたい部品も、何かの行動か機体から推論規則でつなぐ必要がある。公理と推論規則から真であると導けない部品は、マシンに入らない。
