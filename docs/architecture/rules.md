# flake_public のあるべき姿

flake_public は、複数のマシンの構成を管理する。
この文書は、flake_public が満たす要件と、要件を満たすために守る二つの規則（規則 A と規則 B）を書く。
規則 A と規則 B をどう実現するかは書かない。

## 要件

1. 変更の範囲をたどれる: 部品を変えたとき、影響を受ける部品を、部品どうしのつながりをたどって特定できる。
2. 行動をやめると専用の設定値も消える: ホストが行動をやめると、行動のためだけにマシンに入っていた設定値も、マシンから消える。
3. 記憶に頼らない: 部品どうしの関係を、人が覚えておかなくてよい。
4. 保証の範囲が分かる: 何が保証され、何が保証されないかがはっきりしている。
5. 管理の負担を増やさない: 部品どうしの関係を記録する一覧表を、部品とは別に作らなくてよい。
6. 行動の単位で選べる: ホストは、行動の単位でマシンの構成を選べる。

## 言葉

- ホスト: 構成の対象になるマシン一台。
- 部品: マシンの構成を組み立てる単位。部品はマシンに入ると、マシンの構成に設定値を加える。
- 行動: 利用者がマシンで行うこと。行動も部品の一つである。ホストは、マシンで行う行動を選ぶ。
- 機体: マシンそのものを表す部品。ホストごとに一つある。
- 判定: 部品ごとに決まる、「部品がマシンに入るか否か」の真偽。
- 公理: 無条件で真になる判定。ホストが選んだ行動の判定と、ホストの機体の判定が公理になる。
- 推論規則: 「部品 X1 から部品 Xn までの判定がすべて真ならば、部品 Y の判定も真」という形の規則。「ならば」の前に書く判定を前件、「ならば」の後に書く判定を後件と呼ぶ。前件は一つ以上、後件は一つである。推論規則は、前件の部品か後件の部品の定義に書かれる。
- 受け取る: 部品 X が、部品 Y の公開する値を使って、部品 X の設定値を決めること。
- 渡す: 部品 X が部品 Y に値を渡し、部品 Y が渡された値を使って部品 Y の設定値を決めること。

## 規則 A（部品がマシンに入るか否か）

部品の判定が真になるのは、公理と推論規則だけを使って、部品の判定が真であると導けるときに限る。
公理と推論規則だけでは真であると導けない部品の判定は、偽とする。
判定が真の部品だけがマシンに入る。

## 規則 B（部品の設定値を決めるもの）

判定が真の部品 X がマシンの構成に加える設定値は、次のものだけで決まる。

- 部品 X の定義
- 判定が真の部品から、部品 X が受け取った値
- 判定が真の部品が、部品 X に渡した値

## 規則から導かれる性質

1. 推論規則の前件に書けるのは、部品の判定だけである。値（ホスト名など）は推論規則の前件に書けないので、部品がマシンに入るか否かは値では決まらない。値を見て部品の設定値をすべて空にすることは、部品がマシンに入るか否かを値で決めることにあたり、規則 A に反する。値を見て設定値の一部を変えることは、規則 B の範囲に入る。
2. 推論規則の前件に「部品の判定が偽」は書けない。ホストが選ぶ行動を減らしても、判定が新しく真になる部品はない。
3. 一つの推論規則の前件に複数の判定を書くと「かつ」になる。部品 Y を後件に持つ推論規則が複数あると、部品 Y の判定は、どれか一つの推論規則の前件がすべて真のときに真になるので、「または」になる。

## 要件と規則の対応

| 要件 | 規則からどう導かれるか |
|---|---|
| 1. 変更の範囲をたどれる | 規則 A により、部品の判定を変えるのは推論規則だけである。規則 B により、部品の設定値を変えるのは、部品の定義と、受け取る値と、渡される値だけである。部品を変えたときに影響を受ける部品は、推論規則と、受け取る関係と、渡す関係をたどって特定できる。 |
| 2. 行動をやめると専用の設定値も消える | 性質 2 により、ホストが行動をやめても、判定が新しく真になる部品はない。行動の判定が偽になると、行動からしか導けない部品の判定も偽になる。規則 A により、判定が偽の部品はマシンに入らない。規則 B により、判定が偽の部品がほかの部品に渡していた値も使われなくなる。ほかの行動からも導ける部品は、判定が真のまま残る。 |
| 3. 記憶に頼らない | 部品どうしの関係は、推論規則と、受け取る関係と、渡す関係だけである。推論規則と、受け取る関係と、渡す関係は、部品の定義に書かれるので、人が別に覚えておく関係はない。 |
| 4. 保証の範囲が分かる | 保証するのは、規則 A と規則 B が成り立つ範囲である。「規則が保証しないこと」に挙げたものは保証しない。 |
| 5. 管理の負担を増やさない | 推論規則と、受け取る関係と、渡す関係は部品の定義に書かれ、部品とは別の一覧表はない。 |
| 6. 行動の単位で選べる | 公理は、ホストが選んだ行動の判定と、ホストの機体の判定だけである。ホストは行動を選ぶことで、マシンの構成を選ぶ。 |

## 規則が保証しないこと

- 実行時の依存: マシンの上で動くプログラムが、実行時にほかのプログラムを名前で呼ぶこと。実行時の依存は、推論規則にも、受け取る関係にも、渡す関係にも現れない。
- 実行時に作られる状態: キャッシュや、プログラムが動作中に作るファイル。
- 利用者のデータ: 部品がマシンに入らなくなったときに利用者のデータを消してよいかは、規則 A と規則 B からは決まらない。
- 外から持ち込む部品の内部: 外から持ち込む部品が、外から持ち込む部品の既定値で有効にしているもの。

## 規則が決めないこと

- どの部品とどの部品を推論規則でつなぐかは、人が決める。必要な推論規則が欠けていると、行動をやめたときに、ほかの行動が必要とする部品の判定も偽になり、ほかの行動で何かが動かなくなる。不要な推論規則があると、行動をやめても、行動のためだけに入っていた部品の判定が真のまま残る。不要な推論規則は何も壊さないので、気づきにくい。
- いつもマシンに入れたい部品も、何かの行動か機体から推論規則でつなぐ必要がある。公理と推論規則から真であると導けない部品は、マシンに入らない。
