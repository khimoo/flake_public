# 補完 (blink.cmp)

高速な補完エンジン。nvim-cmp の後継的な位置づけ。

- 設定ファイル: `lua/plugins/cmp.lua`

## 機能

| 機能 | 説明 |
|------|------|
| LSP 補完 | 関数名・型名・変数名などを LSP から取得 |
| パス補完 | ファイルパスを `/` や `./` 入力時に補完 |
| バッファ補完 | 現在のバッファ内の単語を補完候補に含める |
| スニペット | 定型パターンの展開（`fn` → 関数テンプレート等） |
| シグネチャヘルプ | 関数の引数入力中に、今どの引数を入力しているか表示 |
| ゴーストテキスト | 補完候補がカーソル位置に薄く表示される |
| ドキュメント自動表示 | 候補選択時にドキュメントが自動でポップアップ |
| コマンドライン補完 | `:` コマンドラインでもパスやコマンドを補完 |

## キーバインド

### 挿入モード（補完メニュー）

| キー | 機能 |
|------|------|
| `<C-space>` | 補完を手動で開く / ドキュメント表示トグル |
| `<C-n>` | 次の候補 |
| `<C-p>` | 前の候補 |
| `<C-y>` | 候補を確定 |
| `<C-CR>` | 候補を確定（kitty keyboard protocol 対応端末のみ。非対応なら `<C-y>`） |
| `<C-e>` | 補完をキャンセル |
| `<C-b>` / `<C-f>` | ドキュメントをスクロール |
| `<C-k>` | シグネチャヘルプの表示/非表示 |
| `<Tab>` | スニペットの次のプレースホルダに移動 |
| `<S-Tab>` | スニペットの前のプレースホルダに移動 |

### コマンドライン（`:` モード）

| キー | 機能 |
|------|------|
| `<Tab>` | 次の候補 |
| `<S-Tab>` | 前の候補 |
| `<C-y>` | 候補を確定 |
| `<C-e>` | 補完をキャンセル |

## ユースケース別の使い方

### 新規ファイルの編集

```
1. ファイルを開いて入力を始める
2. LSP が起動していれば、数文字入力で候補が自動表示される
3. <C-n>/<C-p> で候補を選び、<C-y> で確定
4. ゴーストテキストが表示されたら <C-y> で即確定もできる
5. パスを入力したいときは ./ や / で始めると自動でパス補完に切り替わる
```

### 関数の呼び出し（シグネチャヘルプ）

```
1. 関数名を補完で入力 → <C-y> で確定
2. ( を入力するとシグネチャヘルプが自動表示される
   例: fn foo(x: i32, y: &str) → 今入力中の引数がハイライトされる
3. 引数を入力 → , で次の引数に移ると、ハイライトも移動する
4. シグネチャが消えた場合は <C-k> で再表示
```

### スニペットの展開

```
1. スニペットのトリガーを入力（例: Rust なら fn, mod, impl 等）
2. 候補に [Snippet] と表示されたら <C-y> で展開
3. 最初のプレースホルダ（関数名等）を入力
4. <Tab> で次のプレースホルダに移動（引数、戻り値の型 etc.）
5. <S-Tab> で前のプレースホルダに戻る
6. 全てのプレースホルダを埋めたら、最後の <Tab> で抜ける
```

### コマンドラインでの補完

```
:e <Tab>        → ファイルパスを補完
:set <Tab>      → Neovim オプション名を補完
:lua <Tab>      → Lua の式を補完
:help <Tab>     → ヘルプタグを補完
:%s/old/new<CR> → 置換（補完は出ないが、:s まで打つと候補が出る）
```

### リファクタリング中の補完活用

```
1. grn で LSP rename を開始 → 新しい名前を入力（バッファ補完が効く）
2. 新しい関数を書くとき → 既存の型名や関数名が LSP 補完で出る
3. use / import 文を書くとき → モジュールパスが補完される
4. 構造体のフィールドアクセス → . を打つとフィールド一覧が出る
```

### 補完が出ないとき

```
- <C-space> で手動トリガー（自動補完が発火しなかった場合）
- LSP が起動しているか確認: :LspInfo または :checkhealth lsp
- バッファ補完は最低2文字入力で発火する
```

## skkeleton との連携

- skkeleton (日本語入力) が有効になると blink.cmp は自動で無効化される
  (`skkeleton-enable-pre` で `vim.b.completion = false`)
- skkeleton が無効になると自動で再有効化される
- 日本語入力中に補完メニューが出て邪魔になることはない

## 補完ソースの優先度

候補の表示順は以下の優先度で並ぶ:

1. **lsp** — LSP からの候補（最も精度が高い）
2. **path** — ファイルパス
3. **snippets** — スニペット
4. **buffer** — バッファ内の単語（フォールバック）
